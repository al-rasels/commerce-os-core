# Database Design

## Technology: PostgreSQL

### Connection Architecture

```
┌──────────────────────────────────────────────────────┐
│                   Prisma Client                       │
│                                                       │
│  ┌──────────────────┐  ┌──────────────────────────┐  │
│  │  Write (Primary) │  │  Read Replica (CQRS)     │  │
│  │  MainPool        │  │  ReadPool                │  │
│  │  (R/W)           │  │  (R/O)                   │  │
│  └────────┬─────────┘  └───────────┬──────────────┘  │
└───────────┼────────────────────────┼──────────────────┘
            │                        │
            ▼                        ▼
    ┌──────────────┐        ┌──────────────┐
    │   Primary    │───────→│   Replica    │
    │   (Write)    │  WAL   │   (Read)     │
    └──────────────┘        └──────────────┘
```

## Migration Strategy

### Zero-Downtime Approach

1. **Expand** — Add new columns/tables without breaking existing code
2. **Migrate** — Backfill data, run in dual-write mode for critical changes
3. **Contract** — Remove old columns/tables after confirming stability

### Directives

- All migrations must be reversible (`prisma migrate dev --create-only`)
- Review SQL before applying to production
- Run during low-traffic windows
- Use `dbgenerated` for default values where possible
- Test migrations against a copy of production data

### Naming Conventions

- Tables: `snake_case` pluralized
- Columns: `snake_case`
- FK columns: `table_name_id`
- Indexes: named by query patterns, not auto-named
- JSON columns: suffix with `_json`
